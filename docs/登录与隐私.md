# 使用自己的账号登录

源码包不包含作者的登录状态、真实数据库、导出记录或登录页面截图。每位使用者都应在自己的电脑和浏览器中登录自己的账号。演示模式不需要任何平台账号。

## 先区分两个入口

- “启动演示.command”或`python scripts/start.py --demo`：8766端口，只显示虚构示例，不连接平台，不使用登录状态。
- “启动工作台.command”或`python scripts/start.py`：8765端口，使用你本机的真实平台会话。

下面的步骤只用于正式模式。不要把账号、密码、验证码或Cookie填入工作台表单、备注、问题反馈或代码仓库。

## 登录自己的1688账号

1. 启动正式工作台，在“选品与比价”页面点击“打开登录浏览器”。
2. 程序打开专用Chrome窗口。在该窗口的1688网页中，使用平台提供的正常登录方式，手动完成扫码、账号验证或验证码。
3. 确认窗口中能正常访问1688后，回到工作台填写关键词与筛选条件，开始采集；若任务此前暂停，点击“已处理，继续1688”。

该Chrome资料默认保存在本机`data/chrome-profile/`，与日常Chrome主资料分开。下次启动会尝试复用本机已保留的会话；平台仍可能要求重新验证。不要把这个目录发给其他人或提交到仓库。

## 登录自己的拼多多账号

1. 在工作台的“比价候选”区域点击“查看 Safari / 登录”。
2. 在刚打开的Safari采集窗口中手动登录拼多多消费者网页；使用自己的账号并自行处理平台验证。
3. 在工作台填写要搜索的关键词，点击“验证 Safari连接”。正常取得商品列表后会显示“Safari 窗口采集已就绪”。
4. 开始比价，或在有暂停任务时选择验证并继续。遇到系统繁忙或访问限制时先停止，按页面提示等待后再人工检查。

Safari会话由使用者本机的Safari管理，同一Safari资料中的其他页面可能共享该会话。若当前登录的是其他账号，请自行确认并按平台正常流程切换账号。项目不会替你导入作者的Safari状态，也不会把Safari会话复制给Chrome。

当前Safari采集需要保留窗口，自动操作不主动切到前台。Chrome无头接入保留备用，尚未通过真实可用性验收。

## Safari权限由使用者自己授予

首次连接时，macOS可能询问是否允许启动工作台的程序控制Safari。请先理解权限范围，再自行决定是否允许。需要检查时，打开“系统设置→隐私与安全性→自动化”，找到实际启动程序下的Safari权限；显示的程序名称取决于从终端、启动器还是其他应用运行。

Safari还需要允许来自Apple事件的JavaScript：在Safari“设置→高级”中启用“显示网页开发者功能”，随后在“开发者”设置中查找“允许来自Apple事件的JavaScript”。不同版本的名称或位置可能略有不同，部分版本在“开发”菜单中提供此项。[Apple开发者设置说明](https://developer.apple.com/documentation/safari-developer-tools/developer-settings)、[显示网页开发者功能](https://support.apple.com/zh-hans/guide/safari/sfri20948/mac)。

这项权限允许AppleScript在Safari网页执行JavaScript；它是系统级浏览器能力。本项目代码将正常操作限定在自己创建的单标签拼多多窗口，但该代码约束不会缩小系统权限本身。程序不替使用者自动开启权限，不要求完整磁盘访问或读取密码。

## 哪些资料保留在本机

- `data/chrome-profile/`：使用者自己的1688专用Chrome资料。
- `data/pdd-chrome-profile/`：若使用备用Chrome接入，保存该使用者自己的拼多多资料。
- Safari登录资料：由Safari自身管理，不放进源码包。
- `data/workbench.sqlite3`、`data/exports/`、`data/backups/`：本机业务资料和备份，默认不公开。
- `data/diagnostics/`：本机诊断资料，也不纳入源码包。

业务备份默认不包含浏览器资料，不能用业务备份把登录状态发给别人。需要退出账号时，请在对应平台网页中正常退出；关闭工作台窗口不等于退出平台账号。

## 公开项目时检查什么

打包脚本按明确范围收集源码和演示资料；真实`data/`、浏览器资料、内部进度、原始截图和登录页截图都不收集。公开截图只来自带“演示”标识的虚构数据界面。

`.gitignore`同时排除本机数据库、常见浏览器凭证文件、环境配置和会话导出文件。以后新增源码、截图或配置，仍应在提交前检查实际文件内容；忽略规则不能移除已经提交的历史记录。
