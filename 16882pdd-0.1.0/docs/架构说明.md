# 架构与文件结构

## 模块化单体

React工作台调用本机FastAPI接口，共享SQLite、任务和导出能力。货源与竞品分别通过提供器接入，原始商品快照与个人运营记录分开保存。

当前只面向个人本机使用，默认监听回环地址。真实模式在8765端口，演示在8766端口；两个模式使用不同数据库及提供器。

## 数据流

1688条件→后台任务→最多20个候选→按当前模式复核→合格货源前5件→关键词竞品→单品销量排序→每件最多5条→正货价差候选→人工保存、备注及导出。

平台原文、来源与时间保留在商品快照中。保存、刷新和导出通过业务接口访问共享资料，刷新不覆盖个人备注和状态。

演示提供器产生虚构快照，复用相同的任务、筛选、排名、价差和运营记录逻辑。启动时生成20件货源及25条竞品，让首次打开就能看见结果；它不连接真实平台，也不读取正式数据目录。

## 接入与生命周期

1688使用专用Chrome资料。拼多多默认使用Safari自身会话，只控制本服务创建的独立单标签窗口。自动操作不主动激活Safari；用户点击查看时再切到前台。权限由用户手动授予，程序不修改系统权限或导出Cookie。

真实页面操作最小间隔6秒、关键词开始最小间隔20秒。系统繁忙或限制访问时停止并记录至少5分钟冷却；不会自动切换浏览器。验证码与登录交给用户处理。

候选及已核验位置保存为检查点；完成的货源组不重复访问。服务重启后需手动继续，超过24小时的断点要求新建检索。Chrome无头可用性仍未通过真实验收。

## 接口边界

- `/api/screenings`：固定20候选及前5件竞品串联。
- `/api/tasks`、`/api/products`：货源任务、快照和资料刷新。
- `/api/competitions`：竞品任务、结果和过程。
- `/api/competitions/{id}/opportunities`：正货价差筛选与导出。
- `/api/selections`：个人选品记录。
- `/api/pdd/session`：当前接入、验证和冷却状态。
- `/api/presets`、`/api/settings`：筛选方案与本机设置。
- `/api/backup`、`/api/restore`：业务资料备份及恢复。

写操作校验本机来源与工作台请求头。没有多用户鉴权系统，不作为互联网托管服务公开部署。
